# 上线前安全检查清单

> 来源：`docs/系统审计报告.md`（34 条发现）。本清单只列**上线前必须处理**的项，以及**与上线无关、现在就该处理**的项。
> 用户已确认：站点**尚未正式上线**，因此"公开仓库里的管理员口令"暂不视为即时风险，**但上线前必须清零**。
> 维护约定：每完成一项就在本文件勾掉并写上日期与证据（命令输出/截图路径），**不要只写"已修复"**。

## A. 与上线无关，现在就该处理

- [ ] **轮换已泄露的第三方凭据**（审计 #5）
  - 证据：公开 git 历史里有 DeepSeek / 百度网盘凭据，且**实测那份百度凭据仍然有效**
  - 为什么不等上线：这些凭据直接对**第三方服务**生效，别人拿到就能操作你的网盘/消耗你的 API 额度，**与站点是否上线无关**
  - 做法：到百度/DeepSeek 后台**重新生成**密钥 → 更新部署环境变量 → 确认旧密钥失效
  - ⚠️ **清理 git 历史没有用**（历史已公开、可能已被抓取），**只能换密钥**
- [ ] **确认镜像不再包含 `appsettings.Development.json`**（审计 #8）
  - 该文件含真实密钥，被 `Dockerfile` 打进镜像层（`.dockerignore` 未排除）→ 改为排除，并**重建镜像**后验证（`docker run --rm <image> cat appsettings.Development.json` 应失败）

## B. 上线前必须处理（按风险排序）

- [ ] **改掉默认管理员口令**（审计 #1，critical）
  - 现状：公开仓库 + `CLAUDE.md` + `docs/交接文档.md` + `deploy/basic-deploy.sh` 明文写着 `admin/admin123`，**附线上地址**；用仓库内 `data/teamportal.db` 的哈希 BCrypt 校验 `admin123 => True`；GitHub API 显示仓库 `visibility: public`
  - 做法（顺序有意义）：① 先在系统设置里改口令 → ② 再从文档与脚本里删掉明文 → ③ 若决定保持公开仓库，确认改后仓库里再无可用凭据
  - 验证：用旧口令登录**必须失败**；文档里搜不到明文
- [ ] **Wiki 删除的路径拼接**（审计 #4，high）
  - `WikiEndpoints.cs:152-155` 用未校验的 `ProjectName/TargetFolder` 拼回收站路径 → staff 可移走任意文件（**含线上 SQLite 主库**）
  - 做法：白名单/规范化 + 断言结果落在回收站根目录内
- [ ] **库存数量上界**（审计 #6，high）
  - `InventoryEndpoints.cs:338-353` 归还数量无上界 → 一次请求即可持久化越界值 → 整表读取 `OverflowException`，**全站库存不可用**
  - 做法：上下界校验 + 越界返回 400；并确认既有越界数据是否需要清理
- [ ] **MCP 工具的角色/部门校验**（审计 #2/#3/#9/#20，high/medium）
  - `Mcp/MaterialTools.cs` 的 `material_checkin`、`material_approve_dept`、`material_reject_request` 与 `ProfileTools` 缺校验 → 成员可代他人归还、跨部门审批、自助写"组织评定"
  - 做法：与对应 HTTP 端点**同一套授权判定**（别各写一份）
- [ ] **知识库可见性校验**（审计 #13，medium）
  - `/api/knowledge/content` 与 `/download` 缺 `Visibility` 校验 → 可读同部门他人 personal 项目
- [ ] **压缩包解压限制**（审计 #12，medium）
  - 无解压后总量/条目数限制 + 临时 zip 不清理（解压炸弹 + 磁盘泄漏）
