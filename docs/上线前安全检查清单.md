## A. 与上线无关，现在就该处理

  - 为什么不等上线：这些凭据直接对**第三方服务**生效，别人拿到就能操作你的网盘/消耗你的 API 额度，**与站点是否上线无关**
  - 做法：到百度/DeepSeek 后台**重新生成**密钥 → 更新部署环境变量 → 确认旧密钥失效
  - ⚠️ **清理 git 历史没有用**（历史已公开、可能已被抓取），**只能换密钥**

  - 已做：`src/TeamPortal/.dockerignore` 排除该文件**且** `TeamPortal.csproj` 里
    `<Content Update="appsettings.Development.json" CopyToPublishDirectory="Never" />` 兜底（两道都留，防将来改成 publish 后 COPY 又重新漏）
  - 本机证据：`dotnet publish -c Release` 输出目录里**只有 `appsettings.json`**，`appsettings.Development.json` 已不存在
  - ⚠️ 仍待：**下一次镜像构建后**用 `docker run --rm <image> ls appsettings.Development.json` 复核（镜像层是历史构建产物，改代码不会回改旧 image）

## B. 上线前必须处理（按风险排序）

- [ ] **改掉默认管理员口令**（审计 #1，critical）
  - 现状：公开仓库 + `CLAUDE.md` + `docs/交接文档.md` + `deploy/basic-deploy.sh` 明文写着 `admin/admin123`，**附线上地址**；用仓库内 `data/teamportal.db` 的哈希 BCrypt 校验 `admin123 => True`；GitHub API 显示仓库 `visibility: public`
  - 做法（顺序有意义）：① 先在系统设置里改口令 → ② 再从文档与脚本里删掉明文 → ③ 若决定保持公开仓库，确认改后仓库里再无可用凭据
  - 验证：用旧口令登录**必须失败**；文档里搜不到明文
- [x] **Wiki 删除的路径拼接**（审计 #4，high）—— 已修（`KnowledgePathGuard.ResolveAllInside`）
  - `WikiEndpoints.cs:152-155` 用未校验的 `ProjectName/TargetFolder` 拼回收站路径 → staff 可移走任意文件（**含线上 SQLite 主库**）
  - 已做：`KnowledgePathGuard.ResolveAllInside(kbRoot, ...)` 规范化并按**路径段**用 `GetRelativePath` 断言落在知识库根内
    （刻意不用 `StartsWith` 前缀比较，见审计 #33）；越界返回 400 并记 Warn
  - 证据：`WikiEndpoints.cs:148-163`、`Services/KnowledgePathGuard.cs`
- [x] **库存数量上界**（审计 #6，high）—— 2026-10-17 已修
  - `InventoryEndpoints.cs:338-353` 归还数量无上界 → 一次请求即可持久化越界值 → 整表读取 `OverflowException`，**全站库存不可用**
  - 已做：`InventoryLimits.IsValidRequestQuantity` 单次上下界 + `IsValidResultingStock` 结果上界，且把上界放进
    `UPDATE ... WHERE Quantity + q <= MaxStock`（防并发叠加绕过），越界 400
  - 证据：`src/TeamPortal/Services/InventoryLimits.cs`、`InventoryEndpoints.cs:347-360`
- [x] **MCP 工具的角色/部门校验**（审计 #2/#3/#9/#20，high/medium）—— 2026-10-17 已修（逐工具核对）
  - 逐工具比对 HTTP 策略后，实际缺口 4 个：`material_checkin`（成员可代他人归还并回加库存，HTTP 要 staff）、
    `material_list_stocktakes`（HTTP 要 staff）、`profile_training_add` / `profile_competition_add`
    （HTTP 在 `/api/admin/profiles` 组内 → 成员可给自己写训练/比赛成绩）；另 `admin_create_user`/`admin_update_user`
    之前允许「部长」而 HTTP 是 `AdminOnly` → MCP 提权
  - 已做：全部改为与 HTTP 同一套 `McpAuth.IsStaff/IsAdmin`；`knowledge_read` 另加 wiki 项目可见性
  - 证据：`Mcp/MaterialTools.cs`、`Mcp/ProfileTools.cs`、`Mcp/AdminTools.cs`、`Mcp/KnowledgeTools.cs`；
    `tests/api/McpToolAuthorizationTests.cs`（成员/游客必须 Forbidden，且守卫在触碰业务逻辑之前）
- [x] **知识库可见性校验**（审计 #13，medium）—— 2026-10-17 已修
  - `/api/knowledge/content` 与 `/download` 缺 `Visibility` 校验 → 可读同部门他人 personal 项目
  - 已做：规则收口到 `WikiProjectVisibility.InvisibleProjectNames`（检索层改为委托它）；两个读端点 + MCP `knowledge_read`
    在路径 ACL 之后**再叠加**项目级可见性，越权 403
  - 证据：`Services/WikiProjectVisibility.cs`、`KnowledgeSearchService.IsWikiProjectVisibleTo`、`KnowledgeEndpoints.cs`；
    `tests/api/WikiProjectVisibilityTests.cs`
- [x] **压缩包解压限制**（审计 #12，medium）—— 2026-10-17 已修（另含审计 #14 clone SSRF）
  - 无解压后总量/条目数限制 + 临时 zip 不清理（解压炸弹 + 磁盘泄漏）
  - 已做：`SafeZipExtractor` 逐条目校验 zip-slip（`Path.GetFullPath` 前缀断言）+ 条目数 ≤5 万 / 单文件 ≤100MB /
    累计 ≤500MB；失败由既有 `catch` 清理半成品目录
  - 同时修 **审计 #14**：`git clone` 加 `OutboundUrlGuard`（拒环回/私网/链路本地/CGNAT/单标签内网名，域名解析结果必须全公网）、
    `-c http.followRedirects=false`、**不再回显 git stderr**（原来是内网探测 oracle）
  - 证据：`Services/SafeZipExtractor.cs`、`Services/OutboundUrlGuard.cs`、`WikiGeneratorService.Workspace.cs`；
    `tests/api/SafeZipExtractorTests.cs`、`tests/api/OutboundUrlGuardTests.cs`
