## 3. 硬规矩（都是踩出来的）

### 3.1 **先提交，再跑门禁**

工作树里只要有**别人的未提交改动**，跑绿也是假的。历史事故：两次提交了"半成品快照"（`CS0103 CleanupWorkspacesAsync does not exist`、`CS0246 'RagStatsService' not found`），因为本地测试跑在含队友未提交代码的树上。

**标准顺序**：`git add <明确路径>` → `git commit` → `git status --porcelain` **必须为空** → 再跑四条门禁。

### 3.2 **禁止 `git add -A` / `git add .`**

多人/多 Agent 并行时会把别人的半成品一起提交。**永远逐个列路径**，提交前 `git status` 核对。

### 3.3 **CRLF 陷阱**

仓库里既有文件是 **CRLF**。用整文件重写会让 diff 变成"整个文件都改了"（出现过 **661 行假 diff**）。改既有文件后自检：

```bash
# 应只剩你要改的行数，不应接近文件总行数
git diff --numstat
```
新建文件统一 LF，但**改既有文件必须保持其原行尾**。

### 3.4 **PowerShell 的路径陷阱**

`web/app/(protected)/...` 里的 `(...)` 会被 PowerShell 当语法/字符类。**一律加引号**，文件操作用 `-LiteralPath`（曾因此覆盖过 `wiki/[id]/page.tsx`）。

### 3.5 **单文件 ≤ 200 行**

改动前就超限的文件**别顺手大重构**，只加不拆可以，但要在回报里说明。既有超限清单见 §9.4。

### 3.6 Git 工作流

`main` 受保护 → 分支 `fix/xxx` `feat/xxx` `docs/xxx` `refactor/xxx` → 门禁绿 → PR → CI 绿 → squash 合并。
Commit 格式：`feat(scope): 描述` / `fix(scope): 描述`。
**合并时用 `gh pr merge --squash --subject "…"`**：如果 commit title 里已写了 `(#NNN)`，GitHub 会再追加一次，出现 `(#107) (#107)` 这种重复（已发生过两次）。

### 3.7 网络不稳

`git push` 到 GitHub 经常失败（`Failed to connect to github.com:443`）。**用重试循环**，经验是 1~12 次内成功：

```powershell
for ($i=1; $i -le 14; $i++) {
  git push -u origin <branch> 2>&1 | Out-String | Write-Output
  if ($LASTEXITCODE -eq 0) { break }
  Start-Sleep -Seconds 18
}
```

## 6. AI / RAG 子系统（重点）

### 6.1 一次提问的完整链路

```
POST /api/ai/chat   (SSE)
  └─ AiProxyService.ChatStream(question, scope, history)
       ① 首轮检索   KnowledgeSearchService.SearchDetailed(question, topK:8, role, dept, uid)
                     ├─ SearchSynonyms.StripQuestionWords()   疑问词只在首尾剔除
                     ├─ SearchSynonyms.Expand()               同义词扩展（syn=）
                     ├─ ExecutePass()                         BM25 分块检索（OR 语义）
                     ├─ HasDistinctiveHit()?                  判"弱"（weak=）
                     └─ 弱 → AlternativeQuery() 再检索一遍并合并（relax=1）
       ② 实时数据   LiveInventoryContext.BuildAsync(question, db)   ← 库存/货位，**每次现查**
       ③ 拼消息     system(AI:SystemPrompt) + history + system(RagInjectionFor(context, live, weak)) + user
       ④ 工具循环   AiProxyService.Agent.cs（最多 AI:MaxToolRounds 轮，模型自己决定要不要再查/翻页）
       ⑤ 最后一轮   stream:true 且不带 tools → 直接以 SSE 返回
```

### 6.2 关键参数与上限（改之前先看这里）

| 项 | 值 | 位置 |
|---|---|---|
| 分块 | 800 字符 / 重叠 100 | `KnowledgeSearchService.Index.cs` |
| 打分 | BM25 k1=1.5 b=0.75 | `KnowledgeSearchService.Tokenize.cs` |
| 词条剪枝 | df > 20000 的 token 整个丢弃 | `Index.cs` |
| 索引文件类型 | **`.md .txt .json .csv .xml`** | `Index.cs` 的 `TextPatterns` |
| 首轮 topK | 8（再按 `≥topScore*5%` 过滤，取 5） | `AiProxyService.cs` |
| 工具轮数 | `AI:MaxToolRounds` 默认 **4**（钳 1..8） | 设置项 |
| 单轮工具调用 | 3 | `KnowledgeToolSession.MaxCallsPerRound` |
| 工具返回总字符 | 48000 | `MaxTotalChars` |
| 单页字符 | 8000 | `MaxPageChars` |
| 工具轮墙钟 | 240s | `AiProxyService.Agent.cs` |
| 同义词表 | `AI:SearchSynonyms`，60s 缓存 | 设置项 / `SearchSynonyms.cs` |
| 弱判据阈值 | df > `max(20, 分块数/100)` 视为通用词 | `Query.cs` |

### 6.3 怎么读 RAG 日志

```
RAG search: q=<有效查询> hits=<命中分块数> returned=<返回文档数> empty=<bool> weak=<bool> syn=<同义词追加数> relax=<0|1>
RAG context: chars=<注入上下文字符数> used=<注入文档数>
RAG live: chars=<实时块字符数>
RAG tools: rounds=<工具轮数> calls=<工具调用数> chars=<工具返回总字符> tools=<工具名×次数>
```

判读经验：
- `weak=True` 但 `returned>0` → 命中的都是通用词，**结果大概率不相关**，此时注入段会警告模型先换词。
- `syn>0` → 同义词表生效了（例如 `怎么借东西` → `q=借东西 领用 物料 syn=2`）。
- `relax=1` → 做了二次检索，或查询被过滤空后退回了原查询。
- `rounds` 越大越贵：**正常情况下 1~2 轮就够**；3~4 轮说明首轮上下文不够好。

### 6.4 AI 相关设置项

`AI:Provider`（`deepseek`|`openai`）、`AI:ApiKey`、`AI:BaseUrl`、`AI:ModelName`、`AI:EnableThinking`、`AI:ReasoningEffort`、`AI:SystemPrompt`（留空=内置默认）、`AI:Temperature`、`AI:MaxToolRounds`、`AI:SearchSynonyms`。

- **`EndpointFor()` 不做 `/v1` 的增删**——填什么用什么，别再"帮你补全"。
- 思考模式下 `temperature` 不生效、改发 `top_p`；`thinking`/`reasoning_effort` **只在 provider=deepseek 时发**；永不发 `extra_body`/`thinking_mode`/已废弃的 penalty 参数。
- 废弃键清理见 `SettingsService.ObsoleteKeys`（`AI:DeepSeekKey`、`AI:DeepSeekBaseUrl`、`AI:BridgingAutoRun`）——老库里的这些行会在启动时被删掉。

### 6.5 同义词表怎么维护（**这是提升命中率最划算的旋钮**）

系统设置 → `AI:SearchSynonyms`，**单行 JSON**，值可为字符串或数组：

```json
{"借":["领用"],"货架":["库位","货位"],"多少钱":["单价"]}
```

- 右侧**必须写知识库里真实出现的词**（否则扩了也没用）。
- 扩展上限 6、长键优先；表写坏 → 退回内置种子表；`{}` → 尊重"清空"；**60 秒生效**。
- ⚠️ 内置表**刻意不收单字「还」**：`还剩多少/还有货吗` 是本系统最常见的库存问法，把「还」映射成「归还」只会灌噪音。

### 6.6 已知弱点（我实测到的，别当成新 bug）

1. **弱判据有假阴性**：分词是滑动 bigram，「数传参数」会切出跨词边界的 **「传参」**；这个词在电子部 C++ 文档里真实存在且足够罕见 → 被当成"有区分度的词命中了" → 判强、不发换词警告。
   实测：`q=数传参数 hits=2452 weak=False syn=0 relax=0`（**按设计应该是 weak=True**）。
2. **"更高效"没兑现**：`怎么借东西` 首轮命中数从 170 降到 73（更准），但仍是 `rounds=3 / 19973 字符`——模型拿到好资料后**仍会自己再搜一遍**。
3. **PDF 不进索引**：`TextPatterns` 只含 md/txt/json/csv/xml。知识库里的 `Pixhawk标准/*.pdf` 能在树里看到、能下载，**但搜不到**。要能搜需要先做 PDF→文本入库（PdfPig 已在依赖里）。
4. **错字纠正/拼音没做**：靠模型自己在工具轮里改写（实测它确实会改 `库防→库房`）。
5. 「桥接伪块」读取路径（`.zhidx.json`）**保留但空转**：线上从未生成过 sidecar，删它收益为零但有耦合风险（见 §10.2）。

## 8. 下载鉴权那一类坑（已修，但要知道为什么）

**根因**：JWT 在 `localStorage`，`window.open("/api/...")` 打开的新标签页**发不出 `Authorization` 头** → 必然 401。

**规矩**：凡是要鉴权的下载，一律走 `api.download()`（内部 `downloadWithProgress`：带 token + 进度 + 30s 响应头超时 + 60s 读空闲超时 + **401 自动清 token 并跳 `/auth/login`**）→ Blob → `saveBlob()`。

- **有回归守卫**：`web/tests/no-window-open-api-guard.test.ts` 扫描 `web/`，断言没有任何 `window.open(` 的第一个参数以 `/api/` 开头（`MarkdownImage.tsx` 的 blob URL 放行）。**新写下载时别绕过它。**
- 曾漏的 4 处：知识库树点 PDF、操作日志导出、请求日志导出、以及 `?path=` 深链接（全局搜索跳知识库的入口，非文本会当文本读 → 静默无反应）。

## 9. 已知未修问题 / 技术债

### 9.1 功能类
- **PDF 不进检索索引**（§6.6.3）——`Pixhawk标准/*.pdf` 搜不到。
- **弱判据假阴性**（§6.6.1）。
- **AI 检索"高效"未达成**（§6.6.2）。
- `/admin/knowledge` 首屏报一次 **React #419**（SSR 阶段 `DOMPurify.sanitize is not a function`）。页面随后正常渲染，但一直没修。
- 深链接指向"树里没有但实际存在"的文件时，会提示「没找到」而不尝试下载（树缓存导致）。
- `docs/物料管理规范.docx` 是**过期**的（`.md` 才是真源），且本机没有 pandoc 无法重新生成。**RAG 也不索引 `.docx`**。

### 9.2 并发/一致性
- 标签模板无乐观锁；`ElementsJson` 丢未知字段。

### 9.3 性能/内存（1.8G 硬约束）
- 索引内存实测工具：`tests/api/KnowledgeIndexMemoryProbe.cs`，**opt-in**：
  `TP_MEM_PROBE=1` + `TP_MEM_PROBE_PATH=<知识库路径>`。
- 合成语料结论：zipf 约 **+100.7 MB**，对抗性上界 **+414 MB**；**真实线上 66MB/4602 篇的增量一直没测过**（本地 KB 只有 1.8MB）。

## 10. 环境级限制与已论证、不建议重走的方案

### 10.1 站点是"公网 IP + 明文 HTTP"→ 非安全上下文
后果：**没有摄像头 / Web Bluetooth / WebUSB**。

### 10.2 精臣（NIIMBOT）标签打印直连：**卡在 HTTP，不是 SDK 不行**
- 包是 `web-4.2.1`，SDK 走 **WebSocket `ws://127.0.0.1:37989`**（本地打印服务 exe 必须装），**不是 Web Bluetooth**——所以"非安全上下文不能用蓝牙"这条**理由不成立**。
- 我实测（Edge 155，本机起了真 WS 服务）：

| 页面来源 | 结果 |
|---|---|
| `http://127.0.0.1:8099` | ✅ OPEN |
| `http://8.137.161.160:3000` | ❌ `ERR_BLOCKED_BY_LOCAL_NETWORK_ACCESS_CHECKS` |
| 同上 + 显式授予「本地网络」权限 | ❌ 仍被拦（`state=granted`） |
| 同上 + 把该 origin 当安全上下文 | ✅ OPEN |

**结论：拦的是"明文 HTTP = 不安全上下文"**（Chrome/Edge 147+ 的 Local Network Access）。
**上 HTTPS 就能用**（首次需用户点一次「允许访问本地网络」），顺带解锁摄像头/蓝牙。
当前替代方案：导出 PDF（§7）→ 拿去精臣软件打印。

### 10.3 已明确"不做"
- 本地 embedding / 向量库（内存约束；需求规格里写作硬边界）。
- 服务器端 AI 摘要生成（英文文档约 1635 篇，token 花费不成立，**已整体移除**，只留空转的 sidecar 读取路径）。
- SystemAgent 改造。

## 11. 协作方式（如果 hermes 也用 Agent Teams）

- **先建共享任务，再派活**；owner 认领 → 完成 → `send_message` 给 lead。**队友绝不执行 git**，提交一律由 lead 做。
- lead 必须**等到 owner 说"已停手"**才提交（否则就是 §3.1 的事故）。
- 写作用域尽量不重叠；契约（接口/JSON 形状）**由 lead 先冻结**再让前后端并行，避免"做到一半改契约"。
- 要求队友**做负向对照**（故意改坏 → 测试必须变红），并在回报里如实写"没做到的/不确定的"。
- 需求描述里**给出已查清的事实**（文件:行、实测数字），队友才不用重复调研。

## 12. 标准改动流程（checklist）

1. `git checkout main && git pull` → 确认干净。
2. 建分支：`fix/xxx` / `feat/xxx` / `docs/xxx`。
3. **先读代码再改**；能用线上 API 实测就先实测（§4.6），别靠猜。
4. 改 → 写测试（含边界与负向对照）→ 单文件 ≤200 行、保持 CRLF。
5. `git add <明确路径>` → commit → `git status --porcelain` **必须为空**。
6. 跑四条门禁（§2），数字与基线对比。
7. `git push`（带重试）→ `gh pr create`（PR 正文写清：现象/根因/改法/**未做到**）。
8. `gh pr checks <n> --watch` → 全绿 → `gh pr merge --squash --subject "…"`。
9. `git pull` → 等 5~13 分钟 → 用 §4.3 确认线上就是你的 commit。
10. **做一次线上功能验证**（API 或真浏览器），把结果写进回报；答句类的东西只能上线人工问一次。
