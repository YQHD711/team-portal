# 内容管理设计（界面文案 + 使用引导）

> 目标：管理员不改代码就能调整界面文案与引导内容；引导按功能独立、按角色分级、可跳过、可重看。
> 默认值写在代码里（受评审与 CI 保护），数据库只存覆盖值，读不到/写错都回落到默认值。

---

## 一、总体架构

```
代码默认值（catalog / tours）
        │  合并（覆盖优先，非法值回落）
        ▼
GET /api/content/texts    GET /api/content/guides      ← 匿名/登录可读
        │
ContentProvider（root layout）
        ├── useCopy()       t("nav.inventory")
        └── useTourDefs()   代码默认 + 后台覆盖
                │
        TourProvider（protected layout）
                ├── 自动触发：路径命中 + 未完成 + 本会话未弹过
                ├── TourOverlay / TourBubble：遮罩挖洞 + 气泡
                └── 进度：PUT /api/me/tours/{key}（本地缓存按 userId 隔离）
```

兜底链：数据库覆盖 → 代码默认 → 调用方 fallback → key 本身。任何一层坏掉都不会白屏。

---

## 二、数据表（一次迁移：AddContentManagement）

| 表 | 主键 | 说明 |
|---|---|---|
| SiteTexts | Key | 文案覆盖值；表里没有的 key = 用代码默认值，删行即恢复默认 |
| GuideContents | TourKey | 引导内容覆盖：Title / StepsJson / Enabled / Version |
| UserTourProgresses | 自增 | (UserId, TourKey) 唯一；Status 只能 in_progress/done/skipped |

- 只为已有 key 存覆盖：后台不能凭空造出界面元素或新引导。
- 删用户级联删进度；删覆盖行不影响任何业务数据。
- 新表变更走 EF 迁移：dotnet ef migrations add <Name> --project src/TeamPortal/TeamPortal.csproj

## 三、接口

| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| GET | /api/content/texts | 匿名 + default 限流 | {key: value} 覆盖字典（登录页也要能配） |
| GET | /api/content/guides | 登录 | 启用的引导覆盖 |
| GET | /api/me/tours | 登录 | 我的全部进度 |
| PUT | /api/me/tours/{key} | 登录 | 幂等 upsert，status 白名单校验 |
| DELETE | /api/me/tours/{key} 或 /api/me/tours | 登录 | 重置单条 / 全部 |
| GET | /api/admin/content/texts | AdminOnly | 覆盖列表 |
| PUT | /api/admin/content/texts | AdminOnly | 批量保存；空值 = 删除覆盖 |
| DELETE | /api/admin/content/texts/{key} | AdminOnly | 恢复默认 |
| GET | /api/admin/content/guides | AdminOnly | 含停用项 |
| PUT | /api/admin/content/guides/{tourKey} | AdminOnly | 覆盖内容；StepsJson 必须是 JSON 数组 |
| DELETE | /api/admin/content/guides/{tourKey} | AdminOnly | 恢复默认 |

所有写操作记 OperationLog（content.update）。

## 四、前端结构

| 文件 | 作用 |
|---|---|
| web/lib/copy/catalog.ts + groups/*.ts | 文案默认值目录（key / 分组 / 说明 / 建议长度） |
| web/lib/tours/types.ts | TourDef / TourStep（步骤级 roles、desktopOnly、action） |
| web/lib/tours/registry.ts | 注册、按角色/路径查找、步骤过滤 |
| web/lib/tours/merge.ts | 后台覆盖合并（非法 StepsJson 回落默认） |
| web/lib/tours/progress.ts | 进度读写（localStorage 缓存 + API 真源） |
| web/components/content/ContentProvider.tsx | useCopy / useTourDefs / refresh |
| web/components/tour/* | TourProvider（状态机）、Overlay（定位/挖洞）、Bubble、Center、HelpButton |
| web/app/(protected)/admin/content/page.tsx | 管理后台两 Tab |

文案用法：const t = useCopy(); t("nav.inventory")。未迁移的组件保持硬编码，不受影响。

锚点约定：data-guide="<tourKey>-<步骤含义>"；侧栏导航自动生成 nav-<路径>。目标 2s 内找不到 → 该步自动跳过（骨架屏/移动端抽屉/权限变化都不会卡死）。

---

## 五、权限分级

- 引导级：TourDef.roles（member / 部长 / admin），成员看不到管理类引导。
- 步骤级：TourStep.roles（同页不同权，如「批量打印」只对 staff 展示）。
- 移动端：desktopOnly 步骤自动剔除（侧栏是抽屉，导航目标不存在）。
- 后端：内容管理写接口一律 AdminOnly；进度只能读写本人。

## 六、新增一条文案

1. 在 web/lib/copy/groups/<模块>.ts 加 key（模块.区域.含义，附 group/desc/max）。
2. 组件里换用 t("key", "原文字")。
3. 跑 npx tsc --noEmit 与 npx eslint。
4. 管理后台「界面文案」立即可改，无需发版。

## 七、新增一条引导

1. web/lib/tours/tours/<key>.ts 写定义（3–6 步，90 秒内）。
2. 目标组件加 data-guide 锚点。
3. registry.ts 注册（roles / entry / autoStart / version）。
4. 补测：注册表结构 + 角色过滤（web/tests/tour-registry.test.ts）。
5. 桌面 + 移动端各走一遍。

改已有引导的文案/顺序 → 改文件或直接用管理后台；version + 1 会让老用户看到「有更新」而不是被强制重放。

## 九、边界与不做项

- 不做：后端 Problem() 错误消息、富文本/Markdown、多语言（i18n）、业务数据字段（人名/物料名）的可配置。
- 品牌设置（队名/副标题/主色）继续在「系统设置」，不迁入内容管理，避免两处入口改同一文案。
- 引导内容只改已有 tour 的文案/步骤/启停/版本；新增引导必须走代码（锚点与默认定义）。
- 后台可编辑不代表可任意长文：文案有 max 提示、后端 4000 字上限、StepsJson 100KB 上限并校验 JSON。

## 十、验证

- 前端：cd web && npx tsc --noEmit、npx eslint .、npx vitest run、npx playwright test
- 后端：dotnet build src/TeamPortal/TeamPortal.csproj、dotnet test tests/api
- 注意：本机部分沙盒环境会拦截子进程（esbuild / testhost 报 EPERM 或「拒绝访问」），此时 vitest / dotnet test / playwright 需在普通终端或 CI 中运行；tsc 与 eslint 不受影响。
