## 0. 本切片的目标 / 非目标

**目标**：一条真实 `.bin` 从拖入 → 首屏诊断报告（3 条规则）→ 证据图表，全链路可用。

| | 内容 |
|---|---|
| 规则 | ① 振动超标 ② 分轴速率环振荡 ③ 滤波有效性 |

**非目标**（不要在本切片做）：MCP Server、对话追问、跨日志对比模式、Tauri 桌面端、
PDF 导出、PX4 ULog 解析器、其余 7 条规则、recharts 全量替换。

### 1.3 解析器：**不要复用 `JsDataflashParser`**

`G:\ardupilot_log_analysis\WebTools\modules\JsDataflashParser\parser.js` 虽然成熟，
但：

1. **GPL-3.0**（`LICENSE` 与 WebTools 一致）。拷进 team-portal 会造成许可污染 → **禁止复制其代码**。
   允许阅读它以**获取格式事实**（事实不受版权保护），实现必须是原创 TS。
2. 无类型（仓库禁止 `any`，且要求 `tsc --noEmit` 干净）。
3. 模块顶层就有 `self.addEventListener("message", …)`（该文件把自己当 worker），
   在主线程/vitest 里导入会炸。
4. 它把**所有**消息类型解码进内存；我们只需要规则用到的那几种。

**结论**：自研 `web/lib/flightlog/dataflash/`，读 `FMT` 动态建布局（DataFlash 格式自描述），
只解码白名单消息类型。格式事实参考 `pymavlink` 的 `DFReader.py`（LGPL，同样只读事实）。

### 1.4 oracle：用 pymavlink 生成黄金对照

本机已装 `pymavlink 2.4.49` + `pandas 3.0.5`（`python 3.14.7`）。
解析正确性**必须**用 pymavlink 对同一份字节做对照，不允许"看起来对"。

⚠️ 注意：`pymavlink` 的连接对象没有 `.fmt`，格式表在 `.formats`（188 条），
参数表在 `.params`（1081 条）。

## 3. 关键实现约定

### 3.1 解析器（`web/lib/flightlog/dataflash/`）

- 纯函数 `parseDataflash(bytes: Uint8Array, opts?): ParseResult`，**可在 vitest 直接调用**
  （不依赖 Worker）。Worker 只是薄壳。
- 只解码白名单消息（至少：`FMT, FMTU, UNIT, MULT, PARM, VIBE, PIDR, PIDP, PIDY, RATE, ATT,
  IMU, FTN1, FTN2, RCOU, CTUN, POWR, BAT, GPS, EV, MODE, ARM, MSG, VER`）。
- `messageCounts` 必须**统计到所有消息**（含未解码），否则缺失判定会误报。
- 多实例消息按实例号拆 `Series`（`VIBE.IMU`、`IMU.I`、`GPS.I`）。
- 值按 `FMTU`+`MULT` 换算为标称单位；拿不到换算表时保持原值并在 `warnings` 记一条。
- 截断/CRC 异常：跳过该记录、累计到 `warnings`，**不要抛异常中断整个文件**。
- 目标性能：9.8 MB 样本 < 500 ms（pymavlink 全量 1.16 s 是基线，我们只解码子集应更快）。

### 3.2 版本感知

- ArduPilot 版本从 `MSG`/`VER` 横幅取（`ArduCopter V4.6.2 (…)`）。
- 数值版本口径 `major*10000+minor*100+patch`（见 `version.ts`），全项目唯一。
- 规则 `appliesTo` 不匹配 → `status="not_applicable"` + `note` 说明，例如
  「本规则要求 ArduPilot ≥ 4.4（需要 PIDR 逐项日志），当前 4.0.3」。

### 3.3 规则输出纪律（**最容易做错的地方**）

| 情况 | 必须输出 |
|---|---|
| 缺 `VIBE` 消息 | `status="missing_required"`, `severity="unknown"`, `note` 写明缺什么 |
| 平台/版本不匹配 | `status="not_applicable"`, `severity="unknown"` |
| 窗口内样本 < 最小样本数 | `status="insufficient_data"`, `severity="unknown"` |
| 检查执行且正常 | `status="passed"`, `severity="ok"` |
| 触发 | `status="fired"`, `severity` 按阈值分档 |

**禁止**：把 unknown 情形写成 `passed`。UI 上「无法判断」和「通过」是两回事。

### 3.4 阈值来源必须有依据

每条规则的阈值必须能指到官方文档（写进 `docLinks`）。本切片采用：

| 规则 | 阈值 | 来源 |
|---|---|---|
| 振动 | `VIBE.VibeX/Y/Z` 标准差 > **30** m/s² = critical；> 15 = warning | ArduPilot 振动文档；`Clip` 增量 ≠ 0 直接 critical |
| PID 振荡 | `PIDx.Err` FFT 主峰 **< 10 Hz** 且峰值功率 > 阈值，分轴输出 | 方案 v2 §4.2（低频=P 过大/结构共振） |
| 滤波 | `FTN1.FtX/Y/Z` 主峰与 `INS_HNTCH_FREQ` 偏离，或 `INS_HNTCH_ENABLE=0` 但存在显著峰 | ArduPilot 陷波文档 |

阈值集中在 `analysis/thresholds.ts`，**不得散落在规则里**，便于日后按真实日志校准。

### 3.5 图表

- uPlot（新依赖，Lead 只加一次到 `web/package.json`）。分析视图**不用** recharts。
- 规则通过 `Finding.charts` 声明要看什么；UI 不写业务判断。
- 不降采样：`Err` 峰值就是证据，削峰等于毁证据。
- 频谱由规则算好放进 `SpectrumData`，UI 不重算 FFT。

## 4. 验收条件（本切片完成的标准）

1. `quad_20260617.bin` 在浏览器里拖入 → **无需点击**直接出首屏报告，含 3 条规则的结论。
2. 有正向对照：至少一条日志能让振动或 PID 规则输出 `critical`（用 `fr_*` 或用户日志）。
3. 解析器：与 pymavlink 在同一段字节上的对照全部一致（字段名、条数、值在浮点容差内）。
4. 规则：每条规则都有 fired / passed / missing_required / insufficient_data 四类 fixture 测试。
5. `web/tests/no-window-open-api-guard.test.ts` 同类**负向对照**保留：规则不得在缺数据时返回 passed。
6. 门禁全绿：`dotnet test tests/api/`、`cd web && npx tsc --noEmit`、`npx vitest run`、
   `CI=1 npx playwright test`。
7. 经 PR 合并，线上用真浏览器跑通一条日志。
