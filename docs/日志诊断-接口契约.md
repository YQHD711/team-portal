`runDiagnosis` 据此回传 `DiagnosisResult.parseStats`（`records / skippedBytes / decodedTypes /

### 0.5.4 诊断历史 API（**已冻结**）

```
POST /api/flight-diagnoses        任意已登录用户
GET  /api/flight-diagnoses        列表：admin/部长看全部，普通队员只看自己创建的
GET  /api/flight-diagnoses/{id}   详情：同上 ACL，越权返回 403
```

`POST` 请求体（全部字段必填，服务端做范围校验；`warnings`/`findings` 是摘要，**不要传文档正文**）：
```jsonc
{
  "fileName": "quad_20260617.bin", "sizeBytes": 10249000,
  "records": 229590, "skippedBytes": 0, "durationSec": 362.1,
  "vehicle": "ArduCopter", "vehicleKind": "copter",
  "firmwareVersion": "4.6.2", "versionNumeric": 40602,
  "parseMs": 196, "analyzeMs": 12,
  "decodedTypes": 81, "totalTypes": 81,
  "critical": 0, "warning": 0, "passed": 5, "unknown": 2,
  "warnings": ["最多 20 条，每条 ≤ 500 字"],
  "findings": [{ "ruleId": "vibration_level", "title": "振动超标（IMU0）",
                 "severity": "critical", "status": "fired", "axis": null }]
}
```
→ `200 { "id": 12, "createdAt": "2026-10-12T..." }`

`GET` 列表 query：`limit`(1..100，默认 20) / `offset`(≥0) / `fileName`(精确匹配，可选)
→ `{ "total": 37, "items": [ { ...上面全部字段..., "id": 12, "createdBy": "admin", "createdAt": "..." } ] }`

表 `FlightDiagnosisRecords`：`Id / FileName / SizeBytes / Records / SkippedBytes / DurationSec /
Vehicle / VehicleKind / FirmwareVersion / VersionNumeric / ParseMs / AnalyzeMs / DecodedTypes /
TotalTypes / Critical / Warning / Passed / Unknown / WarningsJson / FindingsJson /
CreatedByUserId / CreatedBy / CreatedAt`。

服务端同时写一条 `LogService.Info("flightdiagnosis", …)`（含 actor、文件名、严重/警告/无法判断数、耗时）
——这就是「运行日志」的服务端落点。

**记录率实测（决定性）**

| 消息 | quad (Copter 4.6.2) | Plane 日志 | 结论 |
|---|---|---|---|
| `PIDR/PIDP/PIDY` | **10.0 Hz**（dt=100 ms） | 10.0 Hz；`fw_0619` 为 25 Hz | Nyquist 仅 5 Hz |

**修正 C1（硬伤）：方案 v2 的旗舰示例「rate error 主峰 6.2 Hz」从 PID 日志里测不到。**
PID 消息默认 10 Hz → Nyquist 5 Hz，6.2 Hz 会混叠成 3.8 Hz。
已用单测固化：`tests/flightlog-spectrum.test.ts` 断言 10 Hz 采样下 6.2 Hz 被混叠。
**要看 6.2 Hz 必须开 `INS_LOG_BAT_MASK=1`，由飞控自身 FFT（FTN1/FTN2）给出。**

**修正 C2（硬伤）：方案 v2 的 PID 频谱判据是误报机器。**
实测「0.8–4 Hz 频带能量占比」在健康与故障日志间完全重叠：

| 日志 | PIDR | PIDP | PIDY |
|---|---|---|---|
| quad（健康） | 0.213 | 0.572 | 0.341 |
| fr_raw | 0.435 | 0.233 | 0.081 |
| fr_batch | 0.381 | 0.425 | 0.027 |
| Plane f0527 | 0.107 | 0.368 | — |
| user_0509 | 0.090 | 0.521 | 0.479 |

16–4506。**任何固定频谱阈值都会对健康日志误报。**
因此规则 2 改为时域 `Err/Tar` 跟踪质量 + 激励门槛，并在证据里如实声明频率域的能力边界。

**修正 C3：单位跨机型差 57 倍，必须换算。**
`PIDx.Tar/Act/Err` 是控制器原生单位：Copter/Sub 为 **rad/s**，Plane/Rover 为 **deg/s**

## 3. 关键实现约定

### 3.1 解析器（`web/lib/flightlog/dataflash/`）

- 纯函数 `parseDataflash(bytes: Uint8Array, opts?): ParseResult`，**可在 vitest 直接调用**
  （不依赖 Worker）。Worker 只是薄壳。
- 只解码白名单消息（至少：`FMT, FMTU, UNIT, MULT, PARM, VIBE, PIDR, PIDP, PIDY, RATE, ATT,
  IMU, FTN1, FTN2, RCOU, CTUN, POWR, BAT, GPS, EV, MODE, ARM, MSG, VER`）。
- `messageCounts` 必须**统计到所有消息**（含未解码），否则缺失判定会误报。
- 多实例消息按实例号拆 `Series`（`VIBE.IMU`、`IMU.I`、`GPS.I`）。
- 值按 `FMTU`+`MULT` 换算为标称单位；拿不到换算表时保持原值并在 `warnings` 记一条。
- 截断/CRC 异常：跳过该记录、累计到 `warnings`，**不要抛异常中断整个文件**。
- 目标性能：9.8 MB 样本 < 500 ms（pymavlink 全量 1.16 s 是基线，我们只解码子集应更快）。

### 3.2 版本感知

- ArduPilot 版本从 `MSG`/`VER` 横幅取（`ArduCopter V4.6.2 (…)`）。
- 数值版本口径 `major*10000+minor*100+patch`（见 `version.ts`），全项目唯一。
- 规则 `appliesTo` 不匹配 → `status="not_applicable"` + `note` 说明，例如
  「本规则要求 ArduPilot ≥ 4.4（需要 PIDR 逐项日志），当前 4.0.3」。

### 3.3 规则输出纪律（**最容易做错的地方**）

| 情况 | 必须输出 |
|---|---|
| 缺 `VIBE` 消息 | `status="missing_required"`, `severity="unknown"`, `note` 写明缺什么 |
| 平台/版本不匹配 | `status="not_applicable"`, `severity="unknown"` |
| 窗口内样本 < 最小样本数 | `status="insufficient_data"`, `severity="unknown"` |
| 检查执行且正常 | `status="passed"`, `severity="ok"` |
| 触发 | `status="fired"`, `severity` 按阈值分档 |

**禁止**：把 unknown 情形写成 `passed`。UI 上「无法判断」和「通过」是两回事。

⚠️ **实测踩过的坑（已修，务必不要回退）**：滤波规则最初在"振动测不出来"时走了"振动在阈值内 → 无需启用陷波 → 通过"这条路，
等于**把未知说成了通过**。现在 `decideNotch` 在 `vibrationUnavailable !== null` 时返回
`vibrationUnmeasurable` → `status="insufficient_data"` / `severity="unknown"`。
**推论：任何"因为 A 正常所以 B 无需处理"的推断，都必须先确认 A 真的被测到了。**

### 3.4 阈值来源必须有依据

每条规则的阈值必须能指到官方文档（写进 `docLinks`）。本切片采用：

| 规则 id | 阈值 | 来源 |
|---|---|---|
| `vibration_level` | `VIBE.VibeX/Y/Z` 标准差 ≥ **30** m/s² 严重、≥ **15** 警告；`Clip` 增量 ≥ **1** 直接严重 | ArduPilot 振动文档，并经 6 份真实日志标定（§1.5） |
| `pid_rate_tracking` | 激励门槛 **10 °/s**；`Err/Tar` ≥ **1.0** 严重、≥ **0.5** 警告；最少 **100** 个样本 | 实测标定（§1.5）+ 官方调参指引；**不是**频谱阈值，理由见修正 C2 |
| `filter_notch` | 机上 FFT 参考 **25 dB**（`FFT_SNR_REF` 默认）；仅当振动 ≥ 15 m/s² 或 clip > 0 才允许建议陷波；`INS_HNTCH_FREQ` 与实测主峰偏差 > **20%** 告警 | ArduPilot 陷波 / FFT 文档 |

阈值集中在 `analysis/thresholds.ts`，**不得散落在规则里**，便于日后按真实日志校准。
