# 雏鹰之翼航模队 · 物料管理规范手册

> 本手册是队内物料管理的执行标准。凡涉及**入库、领用、归还、盘点、报损、采购**，以本手册为准；
> 与系统界面提示冲突时，以本手册为准并及时反馈修订。
> 配套：`docs/使用指南.md`（界面怎么点）。

---

## 1. 目的与适用范围

- **目的**：让每一件物料**有账、有主、有位、有据**——数量对得上、位置找得到、去向查得清。
- **范围**：队内所有可编号管理的器材（电子元器件、结构材料、工具设备、耗材、动力系统、飞控系统、通信设备、电池电源等）。
- **载体**：系统「物料管理」下的**零件库存 / 物料布局 / 领用管理 / 盘点 / 采购申请**，以及「损坏/遗失报备」。

## 2. 角色与权责

| 角色 | 可以做什么 | 不可以做什么 |
|---|---|---|
| 队员 | 查看库存与布局、提交领用、提交采购申请、报备损坏/遗失、执行被分派的盘点 | 直接改库存数量、改等级/单价、删除物料 |
| 部长 | 队员全部 + 新增/编辑物料、导入 Excel、审批本部门领用、发起与分派盘点、审批采购 | 越过管理员审批 A 级领用的终审 |
| 管理员 | 全部权限，含 A 级终审、定责与赔偿、系统设置（低库存阈值、等级过滤等） | —— |

**原则一：账目只能通过流程变动**（领用/归还/盘点入账/采购入库），任何人不得为了"对齐数字"直接改数据库或绕过审批。

**原则二：管理员操作同样留痕受审计。** 管理员领用是"直接放行"，但每一步都会写入操作日志（操作人、时间、来源 IP），可被追溯。权限大不等于没有记录——**越是管理员，越要按流程走**，因为你的记录是别人对账时的唯一依据。

## 3. 物料分级规范（A / B / C）

等级由**单价**自动判定，也可在表单里手动调整（手动修改后界面会标注"已手动修改"）：

| 等级 | 判定（按单价） | 含义 | 管理要求 |
|---|---|---|---|
| **A** | ≥ ¥1000 | 关键贵重 | 领用需**管理员终审**；**归还必须上传照片 + 填写功能测试说明**，且由管理员/部长操作 |
| **B** | ¥100–999 | 常规器材 | 走本部门部长审批；正常归还 |
| **C** | < ¥100（或无单价） | 耗材 | **自助领用**（无需审批）；**没有归还**，领用即消耗 |

- **单价是确定等级的主要依据**，录入时必须填真实单价，否则贵重件会被当成耗材自助领走。
- **注意"自动定级"的真实行为**（与早期描述不同，务必看清）：
  - **新建**物料时，等级初值默认是 **C**；单价填入且 > 0 时才会自动改判。
  - **编辑**已有物料时**清空单价不会自动降级**——一件 A 级物料把单价删掉，它仍是 A 级。
  - 表单里的**等级下拉框随时可以手动选**，手动选择会覆盖自动判定。
  - 结论：**"单价留空就会落 C 级"只在新建且没有手动选级时成立**。不要指望系统替你兜底。
- **规范要求（由人守住，系统当前不拦）**：新增/编辑物料时**单价必填**。确因赠品、拆机件等原因无单价时：
  - 只能落在 **B 级或以上**，**不得留作 C 级**（C 级是自助领用，无人把关）；
  - 并在**备注里写明原因**（如"赠品无单价，估 ¥1200"）。
- 等级不是"重要程度标签"，不要凭感觉改；确有必要时由部长/管理员修改并在备注说明理由。

## 4. 物料字段填写规范

| 字段 | 要求 | 反例 |
|---|---|---|
| **名称** | 通用名 + 关键规格。`品牌 型号 规格`，如 `DJI E305 电机 920KV`、`3S 2200mAh 25C 锂聚合物电池` | ❌ `电机`、❌ `新买的那个` |
| **分类** | 必须从字典里选（见附录 A） | ❌ 自造分类 |
| **数量** | 整数、**当前可用库存**。领用一经批准就扣减，所以**已借出未归还的部分不计入这个数字**（实物还在队里，但不在架上） | ❌ 估算值、❌ 把已借出的也加进来 |
| **单价** | 人民币单价，尽量按实际采购价；决定等级与"库存总价值" | ❌ 留空（见第 3 节，贵重件留空会被当耗材领走） |
| **等级** | 由单价自动判定，一般不改 | ❌ 全部手动设 A |
| **归属部门** | 该物料的主要使用部门；共用件留空。**仅用于说明归属，不参与审批流转**（见第 8.1 节） | —— |
| **项目标签** | 专用于某项目的物料标注项目名（如 `CUADC2026`） | ❌ 把项目塞进名称里 |
| **库位编码** | 由「房间 → 元素 → 层 → 位」联动生成，**不要手敲**（见第 5 节） | ❌ `A架第3层大概` |
| **照片** | A 级建议上传；相同物料可复用 | —— |

**数量口径的直观理解**：一件记录代表"**架子上能拿的**"数量。5 个电池借出 2 个后，数量显示 `3`；这 2 个还回来，数量回到 `5`。想要"队里一共几件"，要看 `数量 + 借出未还数`，后者在「领用管理」里按 `approved` 状态统计。

**命名一致**：同一种物料只建一条记录。发现重复时，由部长/管理员合并（保留一条，把数量并进去），不要长期并存。

## 5. 库位与布局规范

### 5.1 编码规则

```
库位编码 = 房间号 - 元素编码 - 层 - 位        例：201-A-3-05
```

| 段 | 规则 |
|---|---|
| 房间号 | 用队里既有房间编号（如 `1012` 实验室、`1030` 库房、`6011` 电子电路/无人机试飞实验室） |
| 元素编码 | 房间内元素顺序字母：`A`、`B`、`C`…（房间内唯一货架编号） |
| 层 | 从 **1** 开始计数（最底层为 1） |
| 位 / 格 / 区 | 从 **1** 开始，两位补零（`05`） |

### 5.2 元素类型与坐标轴（正视细节视图的称呼不同）

| 元素类型 | 网格称呼 | 说明 |
|---|---|---|
| 立体货架 | **层 × 位** | 常规货架 |
| 柜子 | **层 × 格** | 抽屉/柜格 |
| 工作台 | **排 × 区** | 桌面分区 |
| 1×1 | 整体挂载 | 不可拆分的大件（整机、大箱体） |

### 5.3 画布与尺寸

- **单位统一 cm**，画布尺寸填写房间实际尺寸（如 `900 × 600 cm`）
- 网格 `20 cm` 一格、`100 cm` 主线；元素长宽用实际尺寸，不要为了好看随意缩放
- 元素之间**留出通道**（建议 ≥ 60 cm），便于取放；门/窗标在平面上
- 元素编码与名称要一致：平面图里的 `A货架` 就是库存里的 `201-A`

### 5.4 挂载规则

- 物料**必须挂到具体格位**（层/位），不要只挂在房间
- 只有确实不可拆分的设备才用"整体挂载"
- 移动物料位置时：**先在平面图里改元素/格位，再到库存表单统一调整**，避免两边不一致

## 6. 物料编码与标签规范

> 目标：实物上贴的标签**扫一下就进系统**，且**搬到哪都不会失效**。

### 6.1 两层标签，各管各的

| 标签 | 贴在哪 | 用什么编码 | 为什么 |
|---|---|---|---|
| **货位标签** | 货架 / 柜子 / 工作台的**格位** | 现有库位编码（`201-A-3-05`） | 位置不动，编码永久有效；扫码 = 打开该格位的物料清单 |
| **物品标签** | 贴在**实物**上（A/B 级） | 本章编码（如 `BAT-LIPO-6S3300MAH-2026-0007`） | 物品会移动、借用、跨房间 |

**铁律：物品编码里绝对不放房间号或库位。** 库位编码是"位置码"（含房号），属于格位不属于物品——
把含房号的编码印在电池上，电池一搬到别的架子，标签就作废了。物品编码只回答"**这是什么**"，
"它现在在哪"由系统里的库位字段回答。

### 6.2 物品编码格式

```
格式：<分类前缀>-<准确物品号>-<型号>-<采购年份>-<4 位序号>

例：BAT-LIPO-6S3300MAH-2026-0007
```

| 规则 | 要求 |
|---|---|
| **前缀** | 从分类字典派生（见下表），2~3 个大写字母 |
| **准确物品号** | 选择相关分类下容易识读的缩写（如 `LIPO` 锂聚合物、`NIMH` 镍氢） |
| **型号** | 选择该物品主要特征型号（如 `6S3300MAH`） |
| **采购年份** | 4 位年份，取**采购当年**（如 `2026`） |
| **序号** | 4 位、**补零**（`0007` 而不是 `7`） |
| **序号作用域** | 按「前缀 + 准确物品号 + 型号 + 采购年份」**这一组合**各自从 `0001` 起。例：`BAT-LIPO-6S3300MAH-2026-0007` 与 `BAT-LIPO-3S2200MAH-2026-0003` 各自独立编号 |
| **字符集** | 只用数字 `0-9` 与大写字母 `A-Z`，**全串统一大写**（`6S3300MAH` 不要写成 `6s3300mah`）。序号段是纯数字，天然不会有易混字符问题 |
| **唯一与复用** | **整串编码全队唯一**；报废/转让后编码停用，**绝不给新物品**（否则历史记录会串） |
| **可读性** | 标签上除二维码外**必须同时印可读编码**（扫码枪坏/磨损时手输兜底） |

**分类前缀表**

| 分类 | 前缀 | 分类 | 前缀 |
|---|---|---|---|
| 电子元器件 | `EL` | 动力系统 | `PW` |
| 结构材料 | `ST` | 飞控系统 | `FC` |
| 工具设备 | `TL` | 通信设备 | `RF` |
| 耗材 | `CS` | 电池电源 | `BAT` |
| 其他 | `XX` | | |

**⚠ 取号是人工环节，最容易出错。** 系统目前**没有物料编码字段**，不会自动生号、不能查重，序号撞车没有任何程序会拦住你。所以取号必须按这个顺序走：

1. 在库存页**搜索同型号**，找出这个组合下已有的最大序号；
2. 新号 = 最大序号 + 1；没有任何记录就从 `0001` 起；
3. 把编码写进**物料名称的开头或备注**（如 `[BAT-LIPO-6S3300MAH-2026-0007] 3S 3300mAh 电池`），让下一个人搜得到；
4. 由部长在月度抽查时核对一遍"有没有重号"。

**判别人**：取号人自己负责查重，**部长负责复核**。发现重号，立即停用其中一个并追查（见 6.5 第 4 条）。

### 6.3 二维码内容

**目标形态**（等系统支持后启用）：

- 一律写**短链**：`https://<队里域名>/i/<编码>`（如 `https://team.example.com/i/BAT-LIPO-6S3300MAH-2026-0007`）
  - 扫码直接进系统看到这件物料：名称、分类、等级、当前库位、在库数量、操作记录
  - 比纯文本编码强：能记录"谁在什么时候扫的"，且不依赖扫码枪
- 纯文本编码只作为**离线兜底**，不是主用法
- 短链里的编码统一大写，避免大小写不一致导致查不到

### 6.4 贴标规范

| 事项 | 要求 |
|---|---|
| 谁贴 | A 级**必须贴**（贵重/关键）；B 级建议贴；C 级耗材**不贴实物**，只贴货位 |
| 贴哪 | 不易磨损、不遮挡铭牌与接口的位置：电池贴侧面（避开膨胀面）、飞控贴侧面、工具贴手柄内侧 |
| 材质 | 户外/油污环境用**覆膜不干胶**；电池仓内用**耐温标签** |
| 货位标签 | 贴在该格位的**边沿**（层板正面外侧），不要贴在物品上；同一货架按"层 → 位"从左到右、从下到上编号 |
| 打印 | 标签打印机直接打印对应大小标签（二维码 + 可读编码 + 名称 + 库位 + 等级） |

### 6.5 编码的登记与维护

1. **先建记录再生号**：在系统里新增该物料（填好名称、分类、单价），再按 6.2 的顺序取号，两者保持一致
2. **搬迁不改码**：物品换了位置，只改系统里的库位字段，**不重印标签**
3. **报废不复用**：状态改为损坏/报废并留档，编码作废；新采购的同型号另外取号
4. **合并同类项**：发现同一编码贴到了两件不同物品上，立即停用其中一个号并追查（说明登记环节出错）
5. 每学期大盘点时**抽查 10% 的标签**：能否扫得到、编码与系统记录是否一致、标签是否脱落

### 6.6 现阶段怎么落地（先看这一节，别照着 6.3 直接印码）

**系统现状（已核对代码）**：

- ❌ 没有「物料编码」字段——编码无处可存，只能写在名称或备注里；
- ❌ 没有自动生号、没有按编码查重；
- ❌ **没有 `/i/<编码>` 短链路由**——照 6.3 印出来的二维码**扫开是 404**。

所以：

| 阶段 | 货位标签 | 物品标签 | 二维码内容 |
|---|---|---|---|
| **现在** | 正常贴（库位编码本身有效） | A/B 级贴，但**只印可读编码 + 名称** | **不要印短链**。要印二维码就指向库存页搜索：`https://<队里域名>/inventory?search=<名称关键词>` |
| **系统支持编码字段 + `/i/` 路由后** | 不变 | 不变 | 按 6.3 改用短链，编码取值、前缀、补零规则与本节一致，**无缝迁移**（已贴的可读编码不必重印） |

> **一句话**：现在**可以**按第 6 节给物品编可读编码、贴在实物上；但**短链二维码要等系统支持后再印**，否则队员扫到的是一堆打不开的码，比不贴更糟。

## 7. 入库规范

### 7.1 单件新增（表单）

1. 名称按第 4 节命名规范填写
2. 选分类 → 填数量与**单价** → 系统自动定级（**单价必填**，见第 3 节）
3. 选「房间 → 元素 → 层 → 位」生成库位（找不到元素说明平面图没画，先去「物料布局」补）
4. 需要时补照片、部门、项目标签
5. 保存后**当场复核**列表里的数量与库位

### 7.2 批量导入（Excel）

- 表头（首行，可中英文）：`名称/Name`、`分类/Category`、`数量/Qty`、`库位/Location/位置`、`状态/Status`、`等级/Grade`、`单价/UnitPrice`
- 规则：名称为空的行跳过；分类为空记 `未分类`；状态为空记 `available`；**等级列优先**，没有等级列就按单价自动判（<¥100→C）
- **导入前必须确认「单价」列非空**：导入时单价为空同样会落 C 级，批量的 C 级贵重件是最难追回的事故
- 导入前**先核对列名与单位**，导入后抽查 5 行；批量导入产生的低库存提醒同批共用同一阈值
- 大批量导入建议分批进行，便于定位问题行

## 8. 领用与归还规范

### 8.1 审批流转（按**申请人**角色 × 物料等级）

| 申请人 | 物料等级 | 流转 |
|---|---|---|
| 队员 | C | **直接放行**（耗材自助） |
| 队员 | A / B（本人有部门且该部门有部长） | 部长审批 → A 级再经**管理员终审** |
| 队员 | A / B（本人无部门 / 本人部门无部长） | 直接进**管理员**审批（避免无人可批） |
| 部长 | B / C | 直接放行 |
| 部长 | A | 管理员终审 |
| 管理员 | 任意 | 直接放行（管理员即终审人） |

**关键澄清：审批看的是「申请人的部门」，不是「物料的归属部门」。**

- 物料表单里的**归属部门只表示这件东西主要给谁用，完全不参与审批流转**。所以**共用件（归属部门留空）不会导致没人审批**——只要申请人有部长，就走部长审批。
- 触发"直接进管理员"的条件是：**申请人本人**没有部门，或申请人所在部门当前**没有任命部长**。
- 部长只能审批**本部门成员**的领用；跨部门的申请请找对应部门部长或管理员。

状态：`待部门审批(pending_dept) → 待管理员审批(pending_admin) → 已批准(approved) → 已归还(returned)`；被驳回为 `rejected`（必须写驳回理由）。

### 8.2 提交领用

- 数量必须 **> 0 且 ≤ 当前可用库存**（系统会拦）
- 备注写清**用途/项目/预计归还时间**（如 `CUADC 备赛多旋翼，赛后归还`）
- 领用一经批准，库存**立即扣减**；扣到 0 时该物料状态自动变为"使用中"
- **⚠ 提交申请时不会锁定库存。** 多个待审批的申请可以同时存在、总需求超过库存。系统按**先批准先得**处理：批到库存不足的那一单会被拒绝并提示"库存不足"。
  - 因此：**要抢的紧俏件，提交后当面催审批**，别以为"提交了就占住了"。
  - 部长/管理员审批时若看到"库存不足"，说明货已被更早批准的申请拿走，需要线下协调而不是反复点批准。

### 8.3 归还

- **C 级耗材不归还**（领用即消耗）
- **A 级归还**：必须上传照片 + 填写功能测试说明，**由管理员/部长操作**（队员界面上会提示）
- B 级归还：正常归还，如有功能异常必须写明
- 归还后数量自动回补；**逾期未还**由部长/管理员催办
- **⚠ 系统不支持部分归还**：归还按**整单**处理（一次性回补领用时的全部数量），界面上没有"归还数量"输入框。
  - **领 5 个只还 3 个**怎么办：先按整单归还 5 个（把 3 个实物放回、2 个的位置留空），然后对那 2 个**提交「遗失报备」**，并在备注写明"需从库存扣减 2 个，待盘点入账"。
  - 不要为了"凑成整单"把没还的东西也点成已归还——那会让库存虚增，属于第 8.4 条禁止的行为。
  - **根治办法**：领用时就按实际拿走的数量提交，不要一次申领远超需要的数量。

### 8.4 禁止事项

- ❌ 借用贵重件（A 级）不登记、不拍归还照片
- ❌ 把耗材当资产反复归还（会虚增库存）
- ❌ 一人多领、代领不写备注
- ❌ 为了凑整单归还，把未归还的实物也点成"已归还"

## 9. 盘点规范

### 9.1 类型与发起

| 类型 | 说明 |
|---|---|
| **周盘点** | 按等级分别发起（A级·关键 / B级·常规 / C级·耗材各一份） |
| **学期大盘** | 学期末/开学初全量核查 |

由部长/管理员在「物料盘点」发起 → **分派核查人**（可手动逐项分派或自动均分）→ 被分派人收到"我的盘点任务"。

### 9.2 状态机

```
进行中(in_progress) ⇄ 已暂停(paused)
      ↓ 全部核查完成
   待入账(pending_merge)   ← 发起者先"冻结结果"
      ↓ 发起者"入账"
   已完成(completed)
（随时可"作废"(cancelled)，记录保留；未入账前也可删除）
```

### 9.3 执行要求

- 核查人必须**实物核对**后填实盘数，不得照抄系统数
- 有差异的项要写**备注**（如 `少了 2 个，疑上次未登记`）
- **冻结后差异以实盘为准入账**；任何人不许在盘点中途私自改库存来"消灭差异"
- 完成后由发起者核对差异清单再入账

### 9.4 盘点期间的并发领用（必须知道）

**系统数的快照是在"发起盘点"那一刻拍下的，不是在"冻结"那一刻。** 而入账的动作是**用实盘数直接覆盖库存数量**。两者合起来的后果是：

> 盘点进行中发生的任何领用、归还、采购入库，**都不会体现在这次的差异里，还会在入账时被实盘数覆盖掉**——那几笔账等于白记。

对应的执行要求：

- **发起盘点前先催还**：把在借的 A/B 级尽量收回，减少期间变动；
- **盘点期间尽量冻结相关物料的领用与归还**（尤其是正在盘的那一级）；确需领用的，先领用、**再开始数**；
- **凡在盘点期间发生的变动，必须写进该项的差异备注**（如 `实盘 3，期间小李领走 1`），发起者入账前逐条核对；
- 入账前**先看一遍操作日志**里这段时间的领用/归还记录，与差异清单对得上再点"入账"。

## 10. 损坏与遗失报备规范

- 类型：**损坏(damage)** / **遗失(loss)**；报备损坏时物料状态自动置为"损坏"
- 描述必须写清：**时间、地点、经过、已采取措施**（例：`9/11 试飞时电机桨叶擦地，桨叶断裂，已回收碎片`）
- 定责（管理员操作）：
  - `待定责(pending)` → 核查后二选一
  - `免责(exempt)`：正常损耗/意外
  - `需赔偿(compensate)`：填赔偿金额，并写处理说明
- **时限**：事故/损坏当天报备，最迟次日；涉及安全的同步在「事故与安全」登记

### 10.1 报备不会自动扣账（最容易误解的一条）

**系统现状（已核对代码）：报损和报遗失都不会改变库存数量。**

- 报"损坏"：只把物料状态置为 `broken`，**数量一个都不减**；
- 报"遗失"：**连状态都不改**，只留一条报备记录；
- 管理员定责完成：仍然**不动数量、不动状态**。

所以**账实不符必须靠盘点收口**，报备只是留痕和定责的依据：

1. 报备 → 2. 管理员定责（免责/赔偿）→ 3. **在下一次盘点里把数量改成实物数，入账**。三步缺一不可，只报备不入账，账永远是错的。

**⚠ 损坏件（`broken`）不会阻止领用**：系统不检查状态，一个已标损坏的物料**仍然可以被正常领走**。所以：

- 报备损坏后，**立即把实物从货位撤下**，或贴上醒目的"已损坏·禁用"标记；
- 需要走赔偿/维修流程的，在备注里写明当前实物存放位置；
- 部长盘点时优先复核所有 `broken` 状态的物料。

## 11. 采购规范

- 流程：`待审批(pending) → 已批准(approved) → 已购买(purchased) → 已入库(received)`；驳回为 `rejected`
- 申请必填：**名称、数量、预计单价、理由**
- 入库时**必须在库存里建/更新对应物料**（含单价与库位），不要只更新采购单状态
- 审批权限：部长/管理员；报表可查月度支出与待审批单

## 12. 低库存与补货规范

- 判定口径：**数量 < 阈值**（阈值由管理员在「系统设置 → 库存」配置，默认 **5**）
- 仪表盘「低库存预警」默认只列 **C 级（耗材）**（由 `Inventory:LowStockGrade` 控制）；库存页的高亮不限等级
- 分级显示：数量 ≤ 阈值/3 为**严重**（红），其余低于阈值为**提醒**（黄）
- 补货时限：**严重 → 3 天内**提交采购申请；**提醒 → 一周内**处理
- 补货后及时更新数量，不要"等盘点时再改"

## 13. 数据与审计

- 所有关键操作（领用、审批、归还、盘点、报备、采购、删除）都会写入**操作日志**，含操作人、时间与来源 IP
- **管理员与部长的操作同样记录在案**，没有"免审计"的角色；审批人、驳回理由、定责结果都可追溯
- 记录**不物理删除**：物料状态用 `available / in_use / broken` 表达；确需清理走「回收站」
- 每周由部长抽查一次操作日志与库存差异，异常在队会上说明

## 14. 日常执行清单

**每周**
- [ ] 处理低库存预警（严重件 3 天内下单）
- [ ] 催办逾期未还的 A/B 级领用（系统没有"逾期"字段，按领用备注里写的预计归还时间人工盯）
- [ ] 完成本周盘点任务并入账差异
- [ ] 复核 `broken` 状态的物料：实物是否已撤下、是否已定责

**每月**
- [ ] 抽查 10 件物料的"账实库位"一致性（数量 + 位置 + 状态）
- [ ] 整理重复/命名不规范的物料记录
- [ ] 核对采购单与库存是否一致
- [ ] 抽查物品编码有没有重号（系统不查重，只能人工）

**每学期**
- [ ] 学期大盘（全量）+ 差异入账
- [ ] 更新平面图（新增/搬动货架后必须更新）
- [ ] 归档损坏/遗失的处理结果（赔偿到位/免责确认）

## 附录 C：常见错误速查

| 现象 | 原因 | 纠正 |
|---|---|---|
| 贵重件被当耗材自助领走 | 单价没填，等级落成 C | 补单价 → 等级自动变 A；追回并补登记。**根治：新增物料时单价必填** |
| 编辑物料时删了单价，等级却没变 | 清空单价不会自动降级 | 手动把等级改回来，并补填单价 |
| 平面图里找不到某个货架 | 房间/元素没画或编码不一致 | 去「物料布局」补画，元素编码与库存一致 |
| 库存数量比实物多 | 归还时虚增 / 领用没登记 / 报备后没入账 | 发起周盘点，差异按实盘入账 |
| 报损了但库存没少 | 报备不改变数量（见 10.1） | 走盘点把数量改成实物数，报备只作留痕 |
| 损坏的件还是被领走了 | `broken` 不阻止领用 | 报备后立即把实物撤下或贴"禁用"标记 |
| 盘点入账后，盘点期间的领用不见了 | 快照是发起时的，入账用实盘数覆盖 | 期间变动写进差异备注；入账前对一遍操作日志 |
| 盘点差异不敢入账 | 怕"改数" | 盘点差异入账是**正规流程**，会留痕；私改库存才是违规 |
| 同一物料两条记录 | 命名不一致导致重复 | 合并成一条，数量相加，另一条停用 |
| 两个物品贴了同一个编码 | 取号时没查重（系统不查重） | 立即停用其中一个号，按 6.2 的取号顺序重新取号 |
| 文档/位置信息对不上 | 物料挂在房间而非具体格位 | 重新挂到层/位 |
| 标签扫不出来 | 印的是纯文本/太小/磨损，或印了尚不支持的短链 | 二维码改用短链前先确认系统已支持 `/i/`；现阶段加大尺寸、覆膜重印可读编码 |
| 物品编码在别处查不到 | 编码里塞了房号，搬家后失效 | 编码只表示"这是什么"，位置写系统字段 |
| 提交了领用却拿不到货 | 申请不锁定库存，先批准先得 | 提交后当面催审批；急件直接找部长/管理员 |
